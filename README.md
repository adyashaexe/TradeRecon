# 📊 TradeRecon

Full-stack trade reconciliation engine — matching internal blotters against broker confirms, classifying exceptions by type, and validating detection accuracy against ground-truth data derived from real S&P 500 market records.

---

## 💼 What is TradeRecon?

TradeRecon is a full-stack trade reconciliation web application that simulates the core daily workflow performed by Operations teams at financial institutions. Every trading day, ops analysts must match thousands of internal trade records against broker confirmations, identify discrepancies, and resolve them before settlement. Missed breaks cause settlement failures, regulatory penalties, and financial loss.

TradeRecon automates this process end-to-end: it ingests two CSV files (an internal blotter and a broker confirm file), runs a typed break classification engine across all records, and surfaces a real-time exception dashboard with match rates, break counts, and per-trade detail. It also validates its own detection accuracy using precision, recall, and F1 scoring against a ground-truth manifest derived from the Kaggle S&P 500 dataset.

---

## ✨ Features

- 📁 **CSV Upload** — drag and drop an internal blotter and broker confirm file directly into the dashboard
- 🔍 **Break Classification Engine** — detects and classifies 6 distinct break types per trade
- 📈 **Match Rate Reporting** — calculates overall match rate and per-type break counts across the full file
- 🧪 **Ground-Truth Validation** — scores engine accuracy (precision, recall, F1) against `break_manifest.json`
- 🗂️ **Filterable Break Report** — filter by status (ALL / MATCHED / BREAK) and search by trade ID or symbol
- 🖱️ **Expandable Row Detail** — click any trade row to expand full break detail inline
- 📡 **REST API Backend** — clean Flask API with reconcile, validate, sample, and health endpoints
- 🧬 **Kaggle Data Pipeline** — `prepare_kaggle.py` derives realistic trades from S&P 500 OHLCV data and injects breaks at configurable rates
- 📦 **Modular Architecture** — data preparation, matching engine, API layer, and frontend are independently testable and deployable

## 🔴 Break Classification

| Break Type | Trigger | Real-World Cause |
|---|---|---|
| `PRICE_MISMATCH` | Price diff exceeds 1% tolerance | Rounding errors, stale reference data |
| `QTY_MISMATCH` | Quantity differs between sources | Partial fill booking differences |
| `SIDE_MISMATCH` | BUY/SELL direction conflict | Counterparty booking error |
| `SETTLE_DATE_MISMATCH` | Settlement dates differ | T+2 vs T+3 convention mismatch |
| `MISSING_IN_BROKER` | Trade in blotter, absent in broker file | Unconfirmed trade, confirm not received |
| `MISSING_IN_INTERNAL` | Trade in broker file, absent in blotter | Broker booked a trade not in front-office system |

## 🚀 Getting Started

### Prerequisites

- Python 3.11+
- Node.js 18+
- A free Kaggle account with an API token

### 1. Clone the Repository

```bash
git clone https://github.com/adyashaexe/TradeRecon.git
cd TradeRecon
```

### 2. Set Up the Backend

```bash
cd backend
python -m venv venv

# Windows
venv\Scripts\activate

# Mac / Linux
source venv/bin/activate

pip install -r requirements.txt
```

### 3. Download the Dataset via Kaggle API

Place your `kaggle.json` token in `~/.kaggle/kaggle.json`, then run:

```bash
pip install kaggle
python -m kaggle datasets download -d camnugent/sandp500 --unzip
```

### 4. Prepare Internal and Broker Files

```bash
python prepare_kaggle.py --input all_stocks_5yr.csv --n 500
```

This samples 500 rows from the S&P 500 dataset, derives trade records (price, quantity, side, settlement date), injects breaks across all 6 categories, and writes three files to `data/`.

### 5. Start the Backend

```bash
python app.py
# API at http://localhost:5000
```

### 6. Launch the Frontend

```bash
cd frontend
npm install
npm run dev
# App at http://localhost:5173
```

## 📡 API Reference

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/reconcile` | Upload internal and broker CSVs, returns full reconciliation report |
| `GET` | `/api/validate` | Loads Kaggle-prepared data and scores engine accuracy vs ground truth |
| `GET` | `/api/sample` | Returns hardcoded sample CSVs for quick UI testing |
| `GET` | `/api/health` | Health check, reports `kaggle_ready` status |

#### Validate engine accuracy

```bash
curl http://localhost:5000/api/validate
```

Returns overall and per-type precision, recall, and F1 score measured against `break_manifest.json`.

## 📦 Dataset

TradeRecon uses the **S&P 500 Stock Data** dataset from Kaggle to derive realistic trade records.

**S&P 500 Stock Data** — [kaggle.com/datasets/camnugent/sandp500](https://www.kaggle.com/datasets/camnugent/sandp500)

Daily OHLCV data for S&P 500 constituent stocks. Each row is transformed into a trade record:

| Raw Column | Derived Field | Logic |
|---|---|---|
| `close` | `price` | Execution price |
| `volume / 1000` | `quantity` | Scaled lot size |
| `close >= open` | `side` | BUY if up-day, SELL if down-day |
| `date + 2 days` | `settlement_date` | Standard T+2 settlement |
| auto-generated | `trade_id` | Sequential `TRD-XXXXXX` |

**Break injection rates (configurable in `prepare_kaggle.py`):**

| Break Type | Default Rate |
|---|---|
| `PRICE_MISMATCH` | 8% |
| `QTY_MISMATCH` | 5% |
| `SIDE_MISMATCH` | 3% |
| `SETTLE_DATE_MISMATCH` | 4% |
| `MISSING_IN_BROKER` | 5% |
| `MISSING_IN_INTERNAL` | 3% |

## 📸 Usage

1. Open the app at `http://localhost:5173`
2. Upload your internal blotter CSV and broker confirms CSV (or click **Load Sample Data**)
3. Click **Run Reconciliation**
4. Review the summary cards: match rate, total breaks, missing trades
5. Filter the break report by status or search by trade ID / symbol
6. Click any row to expand full break detail
7. Hit `GET /api/validate` to score engine accuracy against the ground-truth manifest
